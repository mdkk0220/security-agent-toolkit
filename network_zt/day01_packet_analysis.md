## 5교시 · TCP

### 문제 5-1 · 직접 실행해 보기

- 출력 세 줄: True
False
443
- 탐지 코드에서 플래그를 `==` 로 검사하면 어떤 일이 생기나요? 둘째 줄을 근거로 설명합니다.
  - 답: flags는 "SYN"과 "ACK"이 들어 있는 목록이다. "ACK" in packet["flags"]처럼 in으로 검사하면 목록 안에 "ACK"이 있는지 확인해서 True가 나온다. 하지만 packet["flags"] == "ACK"는 목록 전체가 문자열 "ACK"와 같은지 비교하므로 False가 나온다. 따라서 플래그가 포함됐는지 확인할 때는 ==가 아니라 in을 써야 함

### 문제 5-2 · TCP 일까 UDP 일까

- ① ~ ⑤ 가 각각 TCP · UDP · ICMP 중 무엇인지: ① TCP · ② UDP · ③ TCP · ④ UDP · ⑤ ICMP( TCP·UDP 둘 다 아님)
- ① 사진 파일 보내기가 TCP 인 이유는 무엇인가요? 파일 데이터가 빠지거나 손상되지 않도록 받은 쪽에서 수신 여부를 확인하고, 빠진 데이터는 다시 보내기 때문
### 문제 5-3 · 세 번의 순서 맞히기

- 세 패킷의 순서와 방향: ㅍ(나) [SYN] 내 PC → 서버 → (다) [SYN, ACK] 서버 → 내 PC → (가) [ACK] 내 PC → 서버
- 🔍 연결을 맺을 때는 세 번인데, 끝낼 때는 왜 네 번인가요?
  - 답: 연결할 때는 서버의 SYN과 ACK를 한 패킷에 함께 보낼 수 있고 종료할 때는 양쪽이 각자 보낼 데이터가 끝난 시점에 FIN을 보내므로, 확인 응답 ACK와 FIN을 합칠 수 없어 보통 네 번 주고 받음

### 문제 5-4 · 같은 서버로 간 두 연결은 무엇이 다른가
