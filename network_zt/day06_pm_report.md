## 5교시 · 왜 도커인가 · 이미지와 컨테이너 · 같이 설치하기

### 문제 5-1 · 설치를 확인하고 첫 컨테이너 실행하기

- (가) `docker --version` 으로 나온 값을 적어 주세요.
  - 쓸 내용: 「Docker version … build …」 한 줄
  - 답: `Docker version 29.8.2, build 7fc2dff`
- (나) 🔍 `docker run hello-world` 출력이 말하는 일의 순서를 5.5 그림의 번호(① ~ ④)에 맞춰 설명해 주세요.
  - 쓸 내용: ① ~ ④ 번호마다 한 일 (클라이언트 · 엔진 · Docker Hub · 컨테이너)
  - 답:
    ① Docker 클라이언트가 Docker 엔진(데몬)에 실행을 요청한다.
    ② 엔진은 로컬에 이미지가 없으면 Docker Hub에서 `hello-world` 이미지를 내려받는다.
    ③ 엔진이 이미지로 컨테이너를 만들고 실행한다.
    ④ 컨테이너의 프로그램이 안내 문구를 출력하고, 엔진이 그 결과를 클라이언트에 전달한다.
- (다) 🔍 `docker images` 에 보인 것과 `docker ps -a` 에 보인 것은 각각 이미지와 컨테이너 중 무엇이고, 어떻게 다른가요?
  - 쓸 내용: ① images 에 보인 것과 그 종류 ② ps -a 에 보인 것과 그 종류 ③ 둘의 차이
  - 답:
    ① `docker images`에는 `hello-world:latest` 이미지가 보였다.
    ② 현재 `docker ps -a`에는 헤더만 나오고 컨테이너 행은 없다. 이미 실행한 명령이 `docker run --rm hello-world`라 종료된 컨테이너가 자동 삭제된 상태다.
    ③ 이미지는 컨테이너를 만들 때 쓰는 실행 템플릿이고, 컨테이너는 그 이미지로 실제 실행한 인스턴스다. `docker images`는 이미지를, `docker ps -a`는 실행 중이거나 종료된 컨테이너를 보여 준다.
- (라) 🔍 `docker images` 출력을 붙여 넣고, `hello-world` 줄의 `IMAGE` · `ID` · `EXTRA` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `IMAGE` · `ID` · `EXTRA` 의 값과 뜻
  - 답:
    `IMAGE`는 이미지 이름과 태그, `ID`는 이미지 식별자(화면에는 축약된 값), `EXTRA`는 추가 표시 정보다. 해당 행의 `EXTRA`는 비어 있다.

```
IMAGE                ID             DISK USAGE   CONTENT SIZE   EXTRA
hello-world:latest   11a3eb1597e8   25.9kB       9.49kB
```

- (마) 🔍 `docker ps -a` 출력을 붙여 넣고, `hello-world` 줄의 `STATUS` · `PORTS` · `NAMES` · `IMAGE` 값과 각각의 뜻을 적어 주세요.
  - 쓸 내용: ① 출력 ② `STATUS` · `PORTS` · `NAMES` · `IMAGE` 의 값과 뜻
  - 답: 현재 확인한 출력에는 컨테이너 행이 없어 `STATUS` · `PORTS` · `NAMES` · `IMAGE` 값도 없다. `--rm` 없이 컨테이너를 실행해 남겨 두면 각 열은 상태, 포트 연결, 컨테이너 이름, 사용한 이미지 이름을 나타낸다.

```
CONTAINER ID   IMAGE     COMMAND   CREATED   STATUS    PORTS     NAMES
```

## 6교시 · nginx 서버 켜고 접속 기록 읽기

### 문제 6-1 · 포트 없이 켜 보고, 포트를 연결해 접속하고, 기록 읽기

- (가) 포트 없이 켠 `web` 에 접속했을 때 어떻게 되었는지 적어 주세요.
  - 쓸 내용: 접속했을 때 나온 화면이나 오류와 `docker ps` 의 PORTS 열
  - 답: 처음 `docker run -d --name web nginx:1.28`로 실행한 뒤 `docker ps`의 PORTS 열은 `80/tcp`였다. 컨테이너 안에서는 80번 포트로 대기하지만 PC 포트에 공개·연결하지 않았으므로 `http://localhost:8080` 같은 PC 주소로는 접속할 수 없다. 이후 컨테이너를 지우고 `-p 8080:80`으로 다시 실행했다.
- (나) 🔍 `-p 8080:80` 이 하는 일을 내 PC의 포트와 컨테이너의 포트로 나눠 설명해 주세요.
  - 쓸 내용: ① 내 PC 쪽 포트 ② 컨테이너 쪽 포트 ③ 연결이 하는 일
  - 답:
    ① 내 PC의 `8080`번 포트 ② 컨테이너의 `80`번 포트 ③ `-p 8080:80`은 PC의 8080번으로 온 요청을 컨테이너의 80번으로 전달한다. `docker ps`에는 `0.0.0.0:8080->80/tcp`와 `[::]:8080->80/tcp`로 표시됐다.
- (다) 🔍 `docker logs web` 출력에서 `GET /` 줄 하나를 붙여 넣고, 접속자 주소 · 시각 · 요청 · 응답 번호를 찾아 적어 주세요.
  - 쓸 내용: ① `GET /` 줄 ② 접속자 주소 · 시각 · 요청 · 응답 번호 네 가지
  - 답:
    `172.17.0.1 - - [19/Oct/2026:14:31:05 +0000] "GET / HTTP/1.1" 200 615 "-" "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/154.0.0.0 Safari/537.36" "-"`
    접속자 주소는 `172.17.0.1`, 시각은 `19/Oct/2026:14:31:05 +0000`, 요청은 `GET / HTTP/1.1`, 응답 번호는 `200`(요청 성공)이다. 이 로그 줄을 셸에 입력했을 때 나온 `bash: 172.17.0.1: command not found`는 로그를 명령어로 실행하려 한 결과일 뿐, nginx 오류가 아니다.

### 문제 6-2 · 컨테이너 안을 들여다보고, 끄고, 지우기

- (가) 컨테이너 안에서 `ls /usr/share/nginx/html` 로 본 파일 이름을 모두 적고, 그중 브라우저의 첫 화면이 어느 파일인지 적어 주세요.
  - 쓸 내용: ① 파일 이름 모두 ② 첫 화면 파일
  - 답: 파일은 `50x.html`, `index.html` 두 개였다. nginx 기본 주소에 접속했을 때 첫 화면으로 제공되는 파일은 `index.html`이다.
- (나) 🔍 `docker stop web` 뒤에 `docker ps` 와 `docker ps -a` 에 각각 `web` 이 보이나요? 차이를 설명해 주세요.
  - 쓸 내용: ① stop 뒤 ps 에 보이는지 ② ps -a 에 보이는지 ③ 차이의 이유
  - 답: `docker stop web` 뒤 `docker ps`에는 `web`이 보이지 않았고, `docker ps -a`에는 `Exited (0)` 상태로 보였다. `docker ps`는 실행 중인 컨테이너만 표시하지만, `docker ps -a`는 중지된 컨테이너도 표시한다. 중지해도 컨테이너 자체는 삭제되지 않는다.
- (다) 🔍 같은 이름으로 다시 `run` 했을 때 나온 오류 문구와, `docker rm` 이 필요한 이유를 적어 주세요.
  - 쓸 내용: ① 오류 문구 ② rm 이 필요한 이유
  - 답:
    ① `Conflict. The container name "/web" is already in use by container "3a62c3bece8a498a21479b37e45b74cdc7c41e51ec52c279a85e67321f003fa3". You have to remove (or rename) that container to be able to reuse that name.`
    ② `stop`은 컨테이너를 멈출 뿐 이름을 차지하는 컨테이너는 남겨 둔다. 같은 이름으로 새 컨테이너를 만들려면 기존 컨테이너를 `docker rm web`으로 삭제하거나 이름을 바꿔야 한다. 삭제한 뒤 `docker ps -a`에서 컨테이너가 사라진 것을 확인했고, `docker stop web`과 `docker rm web`은 이미 삭제된 이름이라 `No such container: web`을 반환했다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(켜는 명령 · 기록 보는 명령 · 정리 방법)
  - 답: nginx는 `docker run -d --name web -p 8080:80 nginx:1.28`로 켜고 `docker logs web`으로 기록을 확인하며, 정리할 때는 `docker stop web` 후 `docker rm web`으로 컨테이너를 삭제한다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 컨테이너를 중지해도 삭제되는 것은 아니므로, 같은 이름을 다시 쓰려면 기존 컨테이너를 삭제해야 한다.

## 7교시 · 내 페이지 연결 · 두 서버 · 올리기

### 문제 7-1 · 컨테이너 안의 변경이 사라지는 것을 보고, 내 폴더를 연결하기

- (가) 컨테이너 안에서 바꾼 뒤 `docker rm -f web` 으로 지우고 다시 켰을 때 화면이 어떻게 되었는지 적어 주세요.
  - 쓸 내용: ① 바꾼 뒤 화면 ② 지우고 다시 켠 뒤 화면
  - 답:
    ① 컨테이너 안에서 `index.html`을 `<h1>inside</h1>`로 바꿨다. 브라우저 화면 자체는 기록에 없지만, 파일 내용은 `cat`으로 확인했다.
    ② 컨테이너를 `docker rm -f web`으로 삭제하고 같은 이미지로 새 컨테이너를 만들었으므로, 컨테이너 안에서만 한 변경은 사라지고 nginx 기본 `index.html` 화면으로 돌아간다. 컨테이너 삭제 후 `docker ps -a`가 비어 있는 것도 확인했다.
- (나) 🔍 컨테이너 안에서 바꾼 내용이 사라진 이유와, `-v` 로 폴더를 연결하면 무엇이 달라지는지 적어 주세요.
  - 쓸 내용: ① 사라진 이유 ② -v 로 연결하면 달라지는 점
  - 답:
    ① 컨테이너 안에서 수정한 파일은 해당 컨테이너의 쓰기 계층에 저장되므로 컨테이너를 삭제하면 함께 사라진다.
    ② `-v "$(pwd)/site-one:/usr/share/nginx/html:ro"`처럼 내 PC의 폴더를 컨테이너의 웹 문서 폴더에 연결하면, 파일이 호스트 폴더에 남아 컨테이너를 새로 만들어도 유지된다. 호스트에서 파일을 수정하면 그 내용이 컨테이너에서 제공되며, `:ro`는 컨테이너에서 읽기만 허용한다.
- (다) 🔍 `MSYS_NO_PATHCONV=1` 없이 `-v` 를 실행했을 때 화면에 무엇이 나왔고 왜 그랬는지 적어 주세요.
  - 쓸 내용: ① 화면에 나온 것 ② 그렇게 된 이유
  - 답: 제공한 기록에서는 환경 변수 없이 실행한 `docker run ... -v "$(pwd)/site-one:/usr/share/nginx/html:ro" ...`이 컨테이너 ID를 출력하며 성공했고, `docker ps`에도 `web-one`이 실행 중으로 보였다. 따라서 이 기록에서는 `-v` 실행 오류가 발생했다고 적을 수 없다. Git Bash(MSYS)는 Docker 명령에 전달하는 경로를 자동 변환할 수 있어 `MSYS_NO_PATHCONV=1`은 이 변환을 막고 컨테이너 경로(`/usr/share/nginx/html`)를 그대로 전달하는 용도다. 뒤이어 붙여 넣은 `[내 PC] ... (읽기 전용)` 도식에서 발생한 `bash: syntax error near unexpected token '('`는 도식을 셸 명령처럼 입력해서 나온 별도 오류이며, `-v` 실행 결과가 아니다.

### 문제 7-2 · 서버 두 대를 띄워 포트로 구분하고, 파일을 고쳐 바로 반영되는지 보기

- (가) 두 주소(`8080` · `8081`)에서 보이는 화면을 각각 적어 주세요.
  - 쓸 내용: 두 주소의 화면 문구
  - 답: 기록에 따르면 `site-one`과 `site-two` 폴더는 만들었지만, 두 폴더 안에 `index.html`을 만든 기록은 없다. HTML을 터미널에 그대로 입력해 `bash: syntax error near unexpected token 'newline'`가 나왔으므로 파일 내용으로 저장되지 않았다. 따라서 두 마운트 폴더가 비어 있다면 `http://localhost:8080`과 `http://localhost:8081` 모두 nginx의 `403 Forbidden` 화면이 나온다. 실제 브라우저 화면은 기록에 없으므로 접속해서 확인해야 한다.
- (나) 🔍 `docker ps` 의 PORTS 열에서 두 서버를 구분해 주는 것은 무엇인가요?
  - 쓸 내용: PORTS 열에서 서버를 구분하는 값
  - 답: 호스트(내 PC) 쪽 포트 번호다. `web-one`은 `8080:80`, `web-two`는 `8081:80`으로 연결해 각기 `http://localhost:8080`과 `http://localhost:8081`에서 접속한다. 두 컨테이너의 nginx 포트는 모두 80번이지만, 호스트 포트가 달라 구분된다.
- (다) 🔍 `:ro` 는 무슨 뜻이고, 왜 읽기 전용으로 연결하나요?
  - 쓸 내용: ① :ro 의 뜻 ② 읽기 전용으로 연결하는 이유
  - 답: `:ro`는 읽기 전용(read-only) 마운트라는 뜻이다. nginx가 호스트의 웹 파일을 제공할 수 있도록 읽기는 허용하면서, 컨테이너 안의 프로세스가 원본 파일을 수정하거나 삭제하지 못하게 해 파일을 보호한다.
- (한 줄) 보안 담당에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 보안 담당이 바로 읽을 수 있는 한 문장(두 서버를 어떻게 띄웠는지)
  - 답: nginx 컨테이너 두 개를 `web-one`은 `-p 8080:80 -v "$(pwd)/site-one:/usr/share/nginx/html:ro"`, `web-two`는 `-p 8081:80 -v "$(pwd)/site-two:/usr/share/nginx/html:ro"`로 실행해 호스트 포트와 읽기 전용 웹 폴더를 각각 연결했다.
