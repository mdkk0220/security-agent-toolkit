## 6교시 · 코드로 계산과 판정

### 문제 6-1 · 지터 함수 직접 만들기

- (가) 직접 만든 `jitter` 함수를 독스트링과 함께 아래 코드 블록에 붙여 넣어 주세요.
  - 쓸 내용: 독스트링을 쓴 함수를 복사해 아래 코드 블록에 붙여 넣기
  - 답: `got`에서 이웃한 응답 시간 차이의 절댓값을 구해 평균을 리턴합니다.

```
def jitter(got):
    """Return the average absolute difference between neighboring response times."""
    total = 0
    for i in range(1, len(got)):
        total = total + abs(got[i] - got[i - 1])
    return total / (len(got) - 1)
```

- (나) 함수를 채운 뒤 실행해 나온 세 줄을 그대로 옮겨 적어 주세요.
  - 쓸 내용: 터미널 출력 세 줄을 복사해 붙여 넣기
  - 답:
    ```text
    회선 A | 지연 21.9 ms | 지터 1.1 ms | 손실 0 %
    회선 B | 지연 42.3 ms | 지터 54.3 ms | 손실 0 %
    회선 C | 지연 41.0 ms | 지터 1.7 ms | 손실 30 %
    ```
- (다) `jitter` 함수의 리턴값은 무엇이고, `measure` 의 어느 줄에서 어떻게 쓰이나요?
  - 쓸 내용: ① 리턴하는 값이 무엇인지 ② 그 값을 받는 줄(`measure` 안)
  - 답: 이웃한 응답 시간 차이의 평균인 지터를 리턴합니다. `measure`의 `jitter_value = jitter(got)` 줄에서 값을 받아 출력에 사용합니다.

### 문제 6-2 · 세 회선을 화상회의 기준으로 판정하기

- (가) 세 회선의 판정 결과(적합 · 부적합)와 걸린 기준을 각각 적어 주세요.
  - 쓸 내용: 「A: … / B: … (걸린 기준 …) / C: … (걸린 기준 …)」
  - 답: A: 적합 / B: 부적합(지터 기준 초과) / C: 부적합(손실 기준 초과)
- (나) 회선 C 는 지연과 지터가 작은데도 왜 부적합인가요? 어제(10/15) 오후 문제 5-2 에서 본 것과 연결해 적어 주세요.
  - 쓸 내용: ① C 의 손실률과 기준 ② 손실이 통신에 주는 영향 한 가지
  - 답: C의 손실률은 30%로 기준 1%를 넘습니다. 손실 패킷은 재전송이 필요하고, 실시간 음성·영상에서는 빠진 조각 때문에 끊김이 생길 수 있습니다.
- (다) 🔍 `ok` 를 `and` 로 이은 이유는 무엇인가요? `or` 로 이으면 회선 B 의 판정이 어떻게 달라지나요?
  - 쓸 내용: ① `and` 로 이은 이유 ② `or` 로 이으면 B 의 판정이 어떻게 달라지는지
  - 답: 세 기준을 모두 만족해야 적합이므로 `and`를 씁니다. `or`로 바꾸면 B는 지연이 기준 이하여서 지터가 초과해도 적합으로 잘못 판정됩니다.
- (한 줄) 고객에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(어느 회선이 되고 안 되는지, 이유 한 가지)
  - 답: 회선 A는 적합하고, B는 지터가 커서, C는 패킷 손실이 30%라 화상회의에 부적합합니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 여러 기준이 모두 만족되어야 하는 판정에는 `and`를 써야 하며, `or`는 하나만 통과해도 적합으로 분류하는 차이가 있음을 배웠습니다.

### 문제 7-1 · tracert 표에서 느려진 구간 찾기

- (가-1) 표 1 에서 지연이 처음 크게 뛴 구간은 몇 번 홉과 몇 번 홉 사이인가요?
  - 쓸 내용: 「… 번 홉과 … 번 홉 사이」 하나
  - 답: 4번 홉과 5번 홉 사이
- (가-2) 그 구간은 우리 회사 쪽일까요, 바깥(통신사)일까요? 근거를 적어 주세요.
  - 쓸 내용: ① 「사내 / 바깥」 하나 ② 근거(사내 홉의 시간 또는 장비 이름)
  - 답: 바깥(통신사·해외) 구간입니다. 1·2번 사내 홉은 1~2 ms이고 4번 통신사 홉도 6 ms인데, 다음 5번에서 48 ms로 크게 증가합니다.
- (나) 🔍 표 2 의 4번 홉은 60 ms 로 큰데 실제 장애가 아니라고 봅니다. 그 근거는 무엇인가요?
  - 쓸 내용: ① 4번 홉의 뒤 홉 시간 ② 그것이 무엇을 뜻하는지
  - 답: 다음 5번 홉은 7 ms로 다시 작습니다. 4번 홉은 자신의 응답에만 늦게 답했을 뿐 이후 패킷은 빠르게 전달하므로 실제 경로 지연 장애로 보기는 어렵습니다.

### 문제 7-2 · SaaS 접속이 느린 고객 진단하기

- (가) 이 고객의 SaaS 접속이 느린 원인 구간은 어디인가요?
  - 쓸 내용: 「… 번 홉과 … 번 홉 사이」 + 어떤 장비 구간인지
  - 답: 4번 홉인 통신사 중계 장비와 5번 홉인 해외 연결 지점 사이입니다.
- (나) 🔍 그 구간은 우리가 고칠 수 있나요? 고칠 수 없다면 고객에게 무엇을 말하고 무엇을 요청하나요?
  - 쓸 내용: ① 「고칠 수 있다 / 없다」 ② 고객에게 할 말 한 문장 ③ 요청할 곳과 붙일 자료
  - 답: 우리가 직접 고칠 수 없는 통신사·해외 연결 구간입니다. 고객에게 사내 구간은 정상이고 통신사 구간에서 지연이 증가했다고 알린 뒤, ping 평균과 tracert 표를 첨부해 통신사에 확인을 요청합니다.
- (다) 이 측정은 한 시각의 값입니다. 이 값만으로 원인을 단정할 수 없는 이유와, 추가로 잴 것 한 가지를 적어 주세요.
  - 쓸 내용: ① 단정할 수 없는 이유 한 가지(한 시각의 값) ② 추가로 잴 것 한 가지
  - 답: 일시적인 혼잡이나 순간 장애일 수 있어 한 번의 측정으로 지속적인 원인을 확정할 수 없습니다. 시간대를 바꾸어 같은 ping·tracert를 반복 측정합니다.
- (한 줄) 고객에게 보낼 답을 한 문장으로 적어 주세요.
  - 쓸 내용: 고객이 바로 읽을 수 있는 한 문장(우리 구간 상태, 원인 구간, 요청할 곳)
  - 답: 사내 구간은 1~2 ms로 정상이며 4~5번 홉 사이 통신사 구간에서 지연이 늘어 통신사에 측정 자료와 함께 확인을 요청하겠습니다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: 한 홉의 응답 시간이 크더라도 뒤 홉이 정상이라면 실제 전달 지연과 구분해야 하며, 지연이 이후 홉까지 유지되는 구간을 찾아야 한다는 점을 배웠습니다.
