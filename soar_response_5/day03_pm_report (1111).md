# 5과목 Day 2 되돌리기 · 사건 처리와 근무 보고 · 오후 (이름 · 2026-11-11(수))

## 5교시 · 기록을 보고 자동이 바꾼 것만 되돌리기

### 문제 5-1

- (가) 실행 출력:

```
--- 단계 1: 4교시가 남긴 파일
잠긴 계정: ['junho', 'dami']
조치 기록: 5 건
차단한 IP: ['198.51.100.90']
--- 단계 2: INC-001 은 오탐으로 확인됨 — 되돌리기
INC-001 dami · 되돌리기 불가 · 세션 2개 → 세션 0개 · 되돌릴 수 없는 조치(세션 종료) — 사용자가 다시 로그인해야 함
INC-001 dami · 계정 해제 · 잠김 → 잠기지 않음 · 되돌리기: 퇴사한 계정의 서버 요청
--- 단계 3: INC-006 도 오탐으로 확인됨 — 되돌리기
INC-006 junho · 되돌리기 불가 · 세션 1개 → 세션 0개 · 되돌릴 수 없는 조치(세션 종료) — 사용자가 다시 로그인해야 함
--- 단계 4: INC-005 도 오탐으로 확인됨 — 되돌리기
INC-005 198.51.100.90 · IP 해제 · 차단됨 → 차단되지 않음 · 되돌리기: 경로 스캔 (120분 뒤 자동 해제)
--- 단계 5: 되돌린 뒤 상태
잠긴 계정: ['junho']
차단한 IP: []
```

단계 5의 잠긴 계정은 `['junho']`, 차단한 IP는 `[]`입니다.

- (나) 4교시 기록에서 `junho`의 계정 잠금은 `잠김 → 잠김`입니다. `before`와 `after`가 같으므로 계정은 자동 조치 전에 이미 잠겨 있었고, `should_undo`의 5·6번이 `False`를 반환해 해제하지 않았습니다. 이 조건이 없으면 오탐 복구 중 `junho`까지 해제되어 자동 조치가 바꾸지 않은 원래 상태를 훼손합니다.

- (다) 세션 종료 기록은 `세션 2개 → 세션 0개`처럼 상태가 달라졌지만, 세션 종료는 `UNDOABLE_ACTIONS`에 있는 계정 잠금·IP 차단이 아니므로 해제만으로 되돌릴 수 없습니다. 그래서 `되돌리기 불가`로 남기고 사용자가 다시 로그인해야 한다고 표시합니다. 이 기록 없이 「모두 원래대로」라고 보고하면 실제로는 세션이 복구되지 않았는데 복구됐다고 잘못 전달하고, 사용자가 접속할 수 없는 원인도 추적하기 어렵습니다.

## 6교시 · 알림 8건 처리 · 근무 보고

### 문제 6-1

- (가) 실행 출력:

```
--- 단계 1: 알림 8건 처리
INC-001 dami -> 조치함 (조치 기록 2건)
INC-002 seoyeon -> 조치하지 않음 (조치 기록 0건)
INC-003 gaeun -> 승인 대기 (조치 기록 0건)
INC-004 jiwoo -> 오탐 종료 (조치 기록 0건)
INC-005 198.51.100.90 -> 조치 실패 (조치 기록 1건)
INC-008 192.0.2.41 -> 승인 대기 (조치 기록 1건)
INC-009 192.0.2.10 -> 조치하지 않음 (조치 기록 1건)
INC-010 gaeun -> 승인 대기 (조치 기록 0건)
--- 단계 2: 조치 기록
INC-001 dami · 계정 잠금 · 잠기지 않음 → 잠김 · 퇴사한 계정
INC-001 dami · 세션 종료 · 세션 2개 → 세션 0개 · 퇴사한 계정
INC-005 198.51.100.90 · IP 차단 · 차단되지 않음 → 차단되지 않음 (확인 실패) · 방화벽 연결 실패
INC-008 192.0.2.41 · IP 차단 · 변경 없음 → 변경 없음 · 여러 계정이 함께 쓰는 IP 라서 담당자 승인 필요
INC-009 192.0.2.10 · IP 차단 · 변경 없음 → 변경 없음 · 허용 목록 IP 라서 차단하지 않음
--- 단계 3: 근무 보고 요약
{'변경됨': 2, '변경 없음': 2, '확인 실패': 1}
잠긴 계정: ['junho', 'dami']
차단한 IP: []
--- 단계 4: 담당자 확인이 필요한 건
INC-003 gaeun : VIP 계정이라 담당자 승인이 필요함
INC-010 gaeun : VIP 계정이라 담당자 승인이 필요함
INC-005 198.51.100.90 : 조치 후 확인 실패 — 방화벽 연결 실패
INC-008 192.0.2.41 : 여러 계정이 함께 쓰는 IP 라서 담당자 승인 필요
```

단계 3 요약은 변경됨 2건, 변경 없음 2건, 확인 실패 1건입니다. 단계 4의 담당자 확인 목록은 4건입니다.

- (나) 단계 2에서 INC-005는 `차단되지 않음 → 차단되지 않음 (확인 실패) · 방화벽 연결 실패`로 기록됐습니다. 방화벽 연결 실패로 차단이 실제 적용되지 않았고, `is_failure`가 사후 상태의 `확인 실패`를 찾아 요약에 따로 셌습니다. 6번이 없으면 함수가 `None`을 반환해 실패로 식별되지 않습니다. 조치 전·후 문자열이 달라 변경됨으로 잘못 분류되어, 차단되지 않은 건이 성공한 조치처럼 보고될 수 있습니다.

- (다) INC-008은 `192.0.2.41`을 `junho`와 `hana`가 공유하므로 담당자 승인이 필요해 승인 대기입니다. 그대로 차단하면 두 사람의 정상 접속도 막힙니다. INC-009의 `192.0.2.10`은 허용 목록에 있는 회사 점검 서버라 조치하지 않았습니다. 차단하면 점검 서버의 스캔이 막힙니다. INC-003과 INC-010은 VIP 계정 `gaeun`에 관한 알림이어서 경로가 승인 필요로 분기되고 승인 대기입니다. 승인 전에 자동 잠금하면 계정 관리자 업무에 지장을 줄 수 있으므로 담당자가 확인해야 합니다.
